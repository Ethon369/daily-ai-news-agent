# 实施与验收清单

## 实施顺序
1. 文档与可行性：完成 PRD、架构、清单；验证模型、来源、SMTP，分别记录状态。
2. Agent：七个工具、参数与路径边界、真实模型适配、轮次预算、执行事件；先命令行再接界面。
3. 数据：迁移、订阅 CRUD、任务队列、历史与结果；验证重启保留。
4. 调度与推送：北京时间去重、补跑、投递幂等与不确定状态。
5. 页面：创建/编辑身份、预览、历史、轨迹、投递状态，前后端联通。
6. 验证：自动测试、真实来源、真实模型、浏览器与邮件分别记录，补充 Docker。
7. 交付：README、依赖、启动脚本、参考说明、录屏脚本。Git 提交需用户明确授权，不能伪造历史。

## 验收用例
- 订阅：参数校验、保存/修改/停用、刷新持久化、不同偏好。
- 工具：五个基础工具成功、无效参数、越界与符号链接；命令注入、超时、输出限制、环境变量隔离。
- Agent：变动调用序列、重复调用、工具失败后调整、正常结束、无效引用、结构修复、轮次/工具/总时间上限。
- 新闻：部分失败、全部失败、空列表、未知时间、旧新闻、重复链接、内网与重定向拦截。
- 调度：北京时间跨日、重复 tick、当天补跑、停用、已失败正式任务不重复创建。
- 投递：预览不自动发送、正式任务发送、认证拒绝、提交不确定、并发重复请求、重启恢复。
- 界面：桌面/平板/手机、键盘操作、空态、错误、刷新、历史与轨迹。
- 交付：干净环境安装、初始化 migration、单 worker、密钥不入库不入 Git。

## 真实验证门槛
自动测试中的假模型和假邮件仅验证控制逻辑。真实模型须调用 API 并保留脱敏轨迹；真实邮件须用户收件确认。Docker 只有实际启动检查通过后才算验证。未完成项必须保留为未验证。
